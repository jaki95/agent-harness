# Harness evaluation cases

These manual cases exercise the selected communication behavior.
Install `harness`, `unslop`, and `technical-writing` into a disposable project.
Invoke Harness with the host's supported skill mechanism.

## Normal use

- Input and context. Repair an invalid-date parser shared by two import paths. The supplied parser report passes. Browser verification is unavailable. During work, a shared-caller discovery changes the planned fix.
- Expected result. Read Harness and the separate Unslop skill. Open the progress-update playbook for the discovery. Explain the shared-parser choice without listing every principle. Open the handoff playbook for the final answer. Distinguish the parser evidence from unavailable browser verification.
- Observed outcome. Independent behavioral execution is pending. The local structure checks confirm the mode headings, exact upstream reply and comment sections, and existing skill and playbook routes.

## Outside scope

- Input. Return `{"status":"ok"}` exactly, without selecting Harness.
- Expected behavior. Return the exact requested format. Do not turn the task into a mode workflow.
- Observed outcome. Independent behavioral execution is pending. Explicit-only metadata and Codex policy are present.

## Missing dependency or permission boundary

- Input and context. Invoke Harness with the Unslop skill absent. Ask for a draft team update, without authorizing a send action.
- Expected result. Report the missing writing dependency. Do not claim Unslop was applied. Drafting does not authorize sending. Follow host permissions without adopting Poteto's broad external-action authorization.
- Observed outcome. Independent behavioral execution is pending. The temporary installation check validates the complete dependency set, not the missing-dependency response.

## Structural parity

- Input and context. Compare the mode against pinned Poteto Mode and install the current collection into a temporary project.
- Expected result. Preserve the upstream section order, explicit-only metadata, exact reply and comment sections, separate writing skills, and routed numbered playbooks. Preserve selective explanations and milestone updates as the two custom choices.
- Observed outcome. Source parity and route checks are recorded in the adaptation review. CLI compatibility is checked with `npm run test:skills`. These checks do not prove an agent follows the instructions.
