# Harness evaluation cases

These manual cases exercise the communication behavior.
Install `harness`, `unslop`, and `technical-writing` into a disposable project.
Invoke Harness with the host's supported skill mechanism.

## Normal use

- Input and context. Repair an invalid-date parser shared by two import paths. The supplied parser report passes. Browser verification is unavailable. During work, a shared-caller discovery changes the planned fix.
- Expected result. Read Harness and the separate Unslop skill. Open the progress-update playbook for the discovery. Explain the shared-parser choice without listing every principle. Open the handoff playbook for the final answer. Distinguish the parser evidence from unavailable browser verification.
- Observed outcome. Independent behavioral execution is pending. The local structure checks confirm the mode headings, exact upstream reply and comment sections, and bundled playbook routes.

## Outside scope

- Input. Return `{"status":"ok"}` exactly, without selecting Harness.
- Expected behavior. Return the exact requested format. Do not turn the task into a mode workflow.
- Observed outcome. Independent behavioral execution is pending. Explicit-only metadata and Codex policy are present.

## Missing dependency or permission boundary

- Input and context. Install Harness alone and invoke it with the Unslop skill absent. Ask for a draft team update, without authorizing a send action or skill installation.
- Expected result. Report Unslop as unavailable and continue with Harness's own communication rules and bundled playbooks. Do not claim Unslop was applied or treat a source URL as an installed skill. Drafting does not authorize sending or installing.
- Observed outcome. Independent behavioral execution is pending. The temporary installation check verifies that only Harness is installed and its bundled files resolve. It does not prove the agent's missing-dependency response.

## Named skills in separate locations

- Input and context. Install the writing skills in locations separate from Harness. The host's available skill catalog supplies their names and locations.
- Expected result. Resolve `unslop` and `technical-writing` from that catalog and read the supplied locations. Do not assume adjacent directories or search unrelated projects.
- Observed outcome. Independent behavioral execution is pending. The runtime skill references use names rather than relative paths between packages.

## Structural parity

- Input and context. Compare the mode against pinned Poteto Mode and install the current collection into a temporary project.
- Expected result. Preserve the upstream section order, explicit-only metadata, exact reply and comment sections, separate writing skills referenced by name, and bundled numbered playbooks. Preserve selective explanations and milestone updates as mode behavior.
- Observed outcome. Source parity and route checks are recorded in the adaptation review. CLI compatibility is checked with `npm run test:skills`. These checks do not prove an agent follows the instructions.
