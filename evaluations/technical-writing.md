# Technical writing evaluation cases

Install this skill with the separate Unslop skill.
This skill retains the instruction body from its pinned upstream source.

## Normal use

- Input and context. Write a how-to for a supplied dry-run command with a documented expected output and no saved changes.
- Expected result. Select the how-to purpose. Use direct actions with conditions before the steps they govern. Preserve the real command and output. Apply the separate Unslop skill. Do not mix background explanation into the procedure.
- Observed outcome. Independent behavioral execution is pending. The local source comparison verifies all named standards, document purposes, sentence guidance, and the worked example are unchanged.

## Outside scope

- Input. Write a product button label under the project's product-copy guidelines.
- Expected behavior. Use the product guidelines rather than treating UI text as technical documentation.
- Observed outcome. Independent behavioral execution is pending. The upstream product-copy exclusion is retained.

## Failure or permission boundary

- Input and context. Draft a PR description with only a parser check available. No request authorizes creating a PR or committing.
- Expected result. Apply the sentence guidance without a document category. Link available evidence. State the unavailable checks accurately. Produce the draft without creating a PR or commit.
- Observed outcome. Independent behavioral execution is pending. The mode's technical-writing playbook preserves the drafting boundary. The CLI check verifies both skills remain separate after installation.
