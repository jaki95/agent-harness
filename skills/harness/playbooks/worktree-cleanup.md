### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

Use available host filesystem, Git, execution, delegation, and matching verification tools within task authorization and host permissions. Resolve named skills through Harness's catalog rules and bundled resources from its installed package. Report unavailable tools, records, controls, or access without claiming an affected step completed. The bundled read-only audit requires Python 3.10+ and Git supporting NUL-delimited porcelain worktree listings. Read `../references/worktree-audit.md` before running it. Current PR lookup uses authenticated gh when available and authorized; ownership and activity receipts come from the host or explicit user evidence. Missing ownership, inactivity, or preservation evidence holds the candidate.

1. Snapshot and audit. Record disk usage on the repository's filesystem with host tools, then run `python3 <Harness-package>/scripts/worktree-audit.py --repo <repo-dir> --base <fresh-trunk-ref> --usage <current-usage-receipt.json> --github --sizes` (the **principle-build-the-lever** skill). Refresh and verify the intended trunk ref through authorized Git operations first; the audit itself does not fetch or mutate refs. It reads paths from `git worktree list --porcelain -z`, preserving spaces and other valid path characters (the **principle-encode-lessons-in-structure** skill). It reports sizes, ages, actual merge evidence, tracked edits, untracked and ignored files, current PR state, and supplied current-project ownership/activity evidence, then suggests a bucket. Size scans can run in the background when the host supports it. Missing gh or host records remain explicit gaps.
2. The bucket is advice, not permission. The pinned and active chats and their delegated worktrees are the real artifact (the **principle-prove-it-works** skill). Get the current-project set through supported host tools or explicit user evidence and cross-check every candidate. Require confirmed ownership, inactivity, and a current-head receipt. An `eligible-for-confirmation` row still needs the deletion gates; incomplete or stale evidence stays on hold.
3. Verify usage before deleting. For held or uncertain rows, use available host delegates to read only the project's relevant records and report whether the chat is pinned or ongoing and which worktrees it and its children touch (the **principle-guard-the-context-window** skill). Without delegation, use bounded inspection. Pinned chats can own arena and repro trees in sibling worktrees even when those names never appear in the sidebar. Treat unavailable activity evidence as unknown, not inactive.
4. Pause on irreversible loss. Tracked edits, untracked files, and ignored content are preservation questions; untracked does not mean disposable. Show the relevant diff or file list and resolve ownership and disposal within task authorization before deleting. A closed PR is not merge evidence. For squash merges, require a merged PR at this exact worktree head; newer local commits remain unmerged. Clean, confirmed owned, merged or explicitly abandoned, and not-in-use candidates proceed within authorization. In-use, unknown, or unresolved preservation cases stay held. Retain committed work through a surviving branch or another confirmed durable ref.
5. Prune the confirmed set. Recheck HEAD, tracked edits, untracked and ignored content, ownership, and activity immediately before each removal. Use the exact Git-listed path. Prefer `git worktree remove <path>` for a clean candidate. Force removal is limited to the specifically reviewed disposable files and authorized candidate. If a directory remains, re-audit that exact path and remove only confirmed disposable residue; never widen the deletion to its parent. Run `git worktree prune` for confirmed stale metadata. Branch refs survive, but confirm retained refs for detached or abandoned work. Re-list worktrees and measure actual filesystem space reclaimed.
6. Simulators and other reclaimers. Use simulator and cache tools only on hosts that expose them. List exact simulator device and runtime IDs, cache paths, ownership, current usage, and preservation constraints. Delete only the confirmed authorized candidates, such as `xcrun simctl delete <device-id>` or `xcrun simctl runtime delete <runtime-id>` on supported Apple hosts. Avoid blanket simulator deletion and blanket cache clearing. Xcode build data, device support, host application snapshots, and package caches may be candidates; an ignored file or a cache label alone does not prove safe disposal. Respect anything the user has said to keep and report unsupported tools.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** repository-filesystem disk usage before and after with actual space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
