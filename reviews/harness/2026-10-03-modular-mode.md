# Harness source adoption

- Skill. `harness`.
- Source ID. `cursor-pstack`.
- Review date. 2026-10-03.

- Decision. Partial adoption.

## Scope

Harness is a working mode with selective explanations, milestone updates, and separate engineering principles.
It routes to separate writing, control, investigation, and engineering skills, four communication playbooks, the Investigation playbook, the Bug fix playbook, the Feature playbook, the Refactoring playbook, the Perf issue playbook, the Hillclimb playbook, both forensics playbooks, the Prototype playbook, the Visual parity playbook, Babysit and Shipping, Autonomous run, Orchestrate, both Autopilots, Multi-phase or multi-PR plan, Session pickup, Pause safely, Worktree and simulator cleanup, and the Opening a PR playbook. Swarm is a separate routed skill. Each engineering and verification principle has its own pinned source entry in the registry.
Execution permissions follow host and task rules. Investigation retains Poteto's delegation patterns through How and Why with host tool bindings and existing model configuration.

## Upstream content

The source is [Poteto Mode](https://github.com/cursor/plugins/blob/23e4138daa01c42d4969f7a5465f82704e64f798/pstack/skills/poteto-mode/SKILL.md).
Harness uses its section order and unchanged reply and comment sections.
The mode metadata includes explicit-only invocation, an icon, a color, and a reminder.
Quoted scalars follow the harness checker convention.
Harness uses Codex's explicit-only policy in `agents/openai.yaml`. The routed writing, investigation, and engineering skills allow implicit invocation so Codex can discover their names and locations for Harness's routes. They can also be selected for their matching tasks outside Harness.
Host support determines whether `/harness`, native mode features, and reminders are available. Codex uses `$harness`.
